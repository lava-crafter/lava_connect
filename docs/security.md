# 安全边界

组码是共享的小写 UUID 标识，不是 secret，也不派生/提供共享密钥。组成员配置不能替代逐对认证配对、信任固定或每设备 capability；没有云端 relay。组同步的双端启用条件和存储升级注意事项见[同步组说明](groups.md)。

**这是开发预览，不是经过审计的安全产品。**

- mDNS 广告、名称、IP 不授予信任。所有功能数据走 QUIC/TLS 1.3。
- 自签名证书替代公共 CA；Rustls 的证书链验证器允许自签名身份，但 TLS CertificateVerify 签名仍由 ring / Rustls 验证，客户端证书强制要求。跳过 CA/hostname 不等于跳过私钥持有验证。
- 身份是完整证书 DER 的 SHA-256，重连严格固定指纹。证书变更必须新配对，不自动覆盖旧授权。
- 六位码源于 TLS exporter 和双方身份；必须两端人工核对目标设备及码，随后两端分别确认。不要接受来源不明的弹窗。
- 未配对会话只能握手和配对；剪贴板接收与发送在核心中独立检查信任、就绪和能力授权。撤销授权立即关闭会话。
- 信任写入失败不升级会话权限，损坏身份文件拒绝加载而不是生成新身份。服务使用独占锁。
- Linux 身份在数据目录，目录 0700、文件 0600。这是**明确的临时受限文件 fallback**，并非 keyring，不能保护被同 UID 或 root 控制的机器。请勿同步、共享或普通备份该目录。
- Android 使用应用私有目录，Rust 身份 AES-256-GCM 加密；加密 secret 由 Android Keystore 包装，禁用应用备份。卸载 / 删除密钥后需重新配对。核心 TLS 私钥在使用时仍会进入进程内存。
- 信任库不含私钥，原子替换。日志不记录剪贴板 payload、密钥或事件 bytes。
- 帧、消息、设备数、队列、待配对会话、命令执行时间都有上限。当前还没有完善的每 IP 配对请求速率控制或生产级 DoS 防护。

已配对即允许该设备发送你开启能力的数据，不代表对端应用可信。剪贴板会覆盖本机内容，勿在不受信任的设备上配对。
Android 后台读取是可选功能，需要用户（通过 Shizuku 或 adb）授予 `READ_LOGS` 和悬浮窗权限。`READ_LOGS` 本身可读取全部系统日志：应用只启动过滤为 `ClipboardService` 错误级别的 logcat，只用于判断本包名是否被拒绝访问剪贴板，不存储、不发送日志内容。悬浮窗权限仅用于从后台启动读取剪贴板的透明 Activity。Shizuku 只在授权时短暂运行一个 UserService，执行固定参数的 `pm grant` / `appops set`（不经过 shell），完成后即退出。带 `android.content.extra.IS_SENSITIVE` 标记的剪贴板不会被后台自动发送。授予后可在系统设置或用 `pm revoke` 撤销。
协议只校验 PNG 的 MIME/基础格式，图片解码由平台层负责；Android 应限制解码尺寸，不把远端文件路径直接交给系统。
系统 keyring、独立安全审计、模糊测试和长期资源/断网压力测试是稳定版发布前的工作。
